## 2. WHAT HABITWISE IS

A mobile wellness app centered on **craving intervention and behavioral self-awareness**,
with a strict **no-dieting philosophy**. It helps users understand and manage food
cravings in the moment via an adaptive questionnaire, learns their personal
trigger patterns over time, and reflects insights back so they learn about themselves.
Long-term vision includes a smartwatch companion for catching cravings in their peak
window (a Windows desktop demo of that concept was previously spec'd: onboarding form,
in-the-moment questionnaire, Electron+React or Python+PySide6 suggested).

**Core philosophy (non-negotiable, enforced across every feature):**
- No dieting, no restriction coaching, no calorie/weight framing, no shame, ever.
- Gradual change; small conscious choices; neutral, curious, self-compassionate tone.
- Not every craving is an enemy. Some branches deliberately give PERMISSION to eat.
- Never coach a user to override genuine physical hunger. This is a hard product rule.

### 4.1 Taxonomy (LOCKED — do not add categories casually; every addition multiplies tree authoring)

Five trigger categories with sub-triggers:
- **Emotional**: stress/overwhelm, boredom, sad/low, anxiety, loneliness, reward/celebration
- **Physical**: genuine hunger, fatigue, thirst-mistaken-for-hunger, hormonal, hangry
- **Environmental**: saw/smelled it (cue_sensory), specific location (cue_location),
  screens (cue_screen), passing a place (cue_route)
- **Social**: others eating (mirroring), event/gathering, being offered, matching the group
- **Routine/habitual**: time-of-day slump, activity pairing, post-meal reflex, transition moments

Eight craving types: sweet, salty/savory, carby/starchy, fatty/rich, crunchy (texture),
specific comfort food, sheer volume, caffeine/energy.

### 4.2 Data model

```js
userTriggerMap = {            // per user, per selected craving type
  sweet: {
    weights: { emotional, physical, environmental, social, routine },  // sum ~1
    counts:  { ... per category, n observed ... },
    peakTimes: ["late_afternoon", "late_night"]
  }
}
interventionEfficacy = {      // per sub-trigger, per technique
  stress: { box_breathing: { tried, helped } }, ...
}
```

Tree = data-driven graph. Question nodes: { id, type:"question", question, select,
answers:[{label, value, next, meta:{category}}] }. Intervention terminal nodes:
{ id, type:"intervention", subTrigger, technique, title, body, intensityAware,
followUp:"did_that_help" }. Author nodes as config/JSON, render generically. The
in-the-moment flow must work offline — no runtime AI calls (deliberate choice:
predefined decision tree over LLM-generated questions, for predictability/offline/cost).

### 4.3 Onboarding questionnaire (one-time, builds coarse priors ONLY)

- Q1 opener: pick top 2–3 craving types (multi-select) — so we only map what matters.
- Per selected craving: Q2 trigger mapping (select UP TO 2 of the 5 categories — his
  explicit choice) + Q3 timing (morning → late night / after meals / no pattern).
- ~7–8 questions total. Wording style he approved: plain, warm, each option has short
  concrete examples ("Salty or savory — chips, fries, snacky stuff").
- Scoring: one category picked → ~0.7 dominant weight; two → ~0.4/0.35 split;
  normalize to sum 1. Q3 → peakTimes. counts start at 0.
- Division of labor: onboarding maps to the 5 BROAD categories only (coarse). The
  in-the-moment tree does the fine sub-trigger splitting. This keeps onboarding short.

### 4.4 In-the-moment adaptive tree

Root logic (where priors pay off):
1. User logs a craving → load userTriggerMap[craving], sort categories by weight.
2. IF top weight ≥ 0.6 AND counts ≥ 5 → open by CONFIRMING the guess ("Feels like this
   might be about stress — is that part of it?") → Yes jumps straight to that category's
   sub-trigger question (skips a step); "Something else" shows remaining categories.
3. ELSE (new user / skipped onboarding / flat map) → show all 5 categories cold.
   Confidence gating is deliberate: never act confident on thin data; show "still
   learning" states instead.

Shared intensity node after every sub-trigger: mild / medium / strong.
**Intensity modulates DOSE only — it does NOT create separate techniques per level.**
(mild = acknowledge + optional delay offer; medium = the technique; strong = technique +
shared urge_surf node + follow-up). Rationale: one technique per sub-trigger with three
wrappers ≈ maintainable; sub-trigger × intensity uniques ≈ ~90 screens, rejected.

Shared urge_surf node: "cravings peak and pass in ~15 min" + 15-minute timer offer.
All Strong paths can point to this single node.

Interventions by sub-trigger (technique keyed to MECHANISM):
- stress → box breathing / step outside (drop the stress spike first)
- boredom → stimulation not food (5-min task, walk, hands busy)
- sad → gentle behavioral activation + self-compassion; texting someone > distraction
- anxiety → grounding (5-4-3-2-1 senses, exhale longer than inhale)
- loneliness → connection is the actual need; "text someone" nudge
- reward/celebration → DO NOT FIGHT. Reframe to conscious enjoyment. No timer.
- genuine_hunger → **EAT. Always.** Protein/fiber suggestion. Never resistance.
- fatigue → is it rest you need? If fuel, something sustaining not a sugar spike
- thirst → glass of water + a few minutes (low-stakes test)
- hormonal → validate, cyclical, not a willpower failure; self-compassion
- hangry → **EAT.** Judgment is impaired at low blood sugar; not the moment for discipline
- cue_sensory → distance from the cue; cues fade fast once out of sight
- cue_location → change location; the spot is a snacking anchor
- cue_screen → hands busy or pause the screen; autopilot check
- cue_route → ride it out now; alternate route next time (flag to Insights)
- mirroring → gut-check hungry vs. matching; joining in is a fine conscious choice
- event → enjoy deliberately; fighting a celebration backfires
- offered → equally fine to accept or pass; easy script for declining
- matching → allowed to opt in on purpose or opt out
- time_slump → most predictable, easiest to pre-plan (flag to Insights)
- activity_pair → insert different action at the same moment, or pre-portion
- post_meal → close the meal differently (tea, teeth); conscious choice after 10 min
- transition → replacement ritual at the exact transition moment

**Permission branches (reward, social, genuine_hunger, hangry) give permission, not
suppression. This is what keeps the app on the right side of its no-dieting philosophy —
an obesity-prevention tool that coaches white-knuckling through real hunger is harmful.**

### 4.5 Learning loop — the tree sharpens per user

Every completed flow logs { craving, category, subTrigger, intensity, technique,
helped: bool, timestamp }. Two updates on completion:
- **Trigger map**: observed category c: weights[c] += α(1−weights[c]); others decay
  by αweights[k]; normalize; counts[c]+=1. **α = 0.15** (gentle; priors dominate early,
  real behavior takes over after ~5–10 logs; tunable — raise for faster adaptation).
  Mis-self-known users migrate automatically (thought emotional, logs environmental).
- **Efficacy**: tried/helped per technique; once enough data, prefer the user's
  higher-hit-rate option where a sub-trigger has alternatives.

### 4.6 Insights tab (two-layer design)

- **Background engine** (invisible): rigorous stats on all logs — time-of-day and
  day-of-week distributions, week-over-week trends, Pearson/Spearman correlations with
  context variables (sleep, hunger, stress, mood), t-tests/Mann-Whitney for group
  comparisons, chi-square for categorical associations, regression to control for
  confounds (weekend vs. just-less-sleep), p-values + effect sizes + n stored per finding.
- **Presentation layer**: plain-English Insight Cards, one observation per card, driver
  named, subtle confidence signal ("strong pattern" / "still learning"). Progressive
  disclosure: tap to expand friendly detail → "see the numbers" toggle exposes the actual
  chart, p-value, effect size, n. Default stays simple; rigor is opt-in.
- **Reflection flow**: weekly/on-demand walkthrough of 3–5 top findings; "does this feel
  true?" (yes / not really / sometimes) feeds back into weighting; ends with ONE small
  non-restrictive suggestion tied to the strongest driver.
- **Small-sample honesty**: gate significance claims behind minimum n; first week or two
  is descriptive "still learning" mode. Never let the engine claim significance off five
  data points.
- Context variables to capture per log (low-friction, quick taps): hunger, mood, stress,
  sleep last night, location/setting, preceding activity, meal-skipped flag, optional note.
- The craving-flow log object is a primary data source for Insights; helped? doubles as
  efficacy feedback. The systems feed each other — no separate pipeline.

## 5. NEXT FEATURE — MEDICAL/PSYCHIATRIC/MEDICATION-AWARE LAYER (designed, NOT built)

Dhruv's idea: adapt questions and strategies based on user conditions, medications, and
current state. Canonical example: stimulant ADHD meds (Vyvanse/Adderall) suppress
appetite while active → rebound hunger in the evening → that craving is a FUELING
problem, not a willpower problem → correct response is a balanced filling meal, possibly
pre-planned before the predictable rebound window, possibly worth discussing with the
prescriber. The full requirements prompt exists as a file (§9) — deliverable is a
research-backed DESIGN PROPOSAL first, no code until he approves.

Key architecture decisions already made (in the prompt file, summarized):
- **Three hooks, not a parallel system**: (A) safety pre-check before tree entry that can
  exit-ramp out of the craving flow entirely; (B) prior seeding — known medical facts
  write directly into userTriggerMap weights/peakTimes instead of being slowly learned;
  (C) intervention filter at terminal nodes (substitute/suppress/annotate techniques).
  New sub-triggers only inside existing branches where mechanism genuinely differs
  (e.g. medication_rebound, under_fueled under PHYSICAL).
- **Use a self-reported diagnosis; NEVER infer or name one.** Symptom-driven fields may
  adjust logic silently but can never surface a condition name to the user. Enforce
  architecturally (separate logic-driving fields from copy-driving fields).
- **No appetite-suppression capability for ANYONE** (global rule, not ED-specific — so
  withholding history can't unlock suppression strategies).
- **Permission interventions exempt from efficacy down-weighting** (otherwise the loop
  could learn "eating didn't help" and stop feeding hungry people — real bug).
- **No medication instructions ever** — timing collected as input only; all med concerns
  → prescriber.
- **Graceful degradation**: no medical profile = exactly current behavior, no nagging.
- **Craving vs. symptom**: hypoglycemia is not a craving; exit ramps, not branches.
- **ED-risk mode is a MODE SWITCH**: disables all delay/suppress/resist interventions,
  keeps permission ones, no quantity tracking, non-accusatory, can't be exited by
  editing answers. Teen + ED risk + medical intake = highest-stakes combo; age is a
  first-class safety variable.
- **Research tiering**: Tier 1 full depth (stimulants, under-fueling, sleep,
  antidepressants, antipsychotics/mood stabilizers, PMDD, diabetes [exit-ramp],
  ED screening); Tier 2 summary; Tier 3 deferred with honest reasoning. Evidence records
  per claim with a product_action_tier (ACT / SOFT / INFORM / DO-NOT-ACT); below-moderate
  confidence can't drive branching. Required: interaction scenarios AND ≥5 "no-change"
  cases (medical info present, standard recommendation correctly unchanged — guards
  against over-medicalizing ordinary cravings).
- **Flagged to Dhruv, undecided**: regulatory posture (FDA general-wellness vs. regulated
  function line as medical adaptation deepens; HIPAA if it ever runs through the family
  practice). He was advised to raise it with whoever handles compliance for the practice.

## 7. GUARDRAILS SUMMARY (apply to ALL future work on this project)

1. Genuine hunger and hangry always route to eating. Non-negotiable.
2. Permission branches stay permissive; conscious choice, never suppression.
3. No shame, moralizing, calorie or weight framing anywhere.
4. No diagnosing, no medication dosing/timing/discontinuation advice.
5. No fabricated certainty — confidence thresholds and "still learning" states.
6. ED safeguards as described; no restrictive/compensatory strategies for anyone.
7. In-the-moment flow works offline; tree is data-driven config.
8. Health data is sensitive — design privacy protections before collecting it.
