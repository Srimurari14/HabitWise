# HabitWise — Production Mobile App Build (Flutter)

Build HabitWise as a production-grade Flutter application for iOS and Android. This is
NOT a prototype or demo — treat it as a real product headed for the App Store and Play
Store. No placeholder screens, no TODO stubs, no mock data left in shipping paths.

Before writing any code, read these docs in the repo and treat them as the source of
truth for all product behavior:
1. HABITWISE_PROJECT_HANDOFF.md — full project context, philosophy, guardrails
2. habitwise_craving_system_spec.md — taxonomy, onboarding, decision tree, learning loop
3. habitwise_intervention_upgrade_prompt.md — swap lists, intensity plans, whyLines,
   food-preference onboarding
4. habitwise_medical_layer_prompt.md — FUTURE feature; do not implement, but architect
   so its three hooks (pre-tree safety check, prior seeding, intervention filter) can be
   added without restructuring

## Stack (locked)

- Flutter, latest stable; Dart with strict analysis (`analysis_options.yaml`, very_good_analysis or equivalent)
- State management: Riverpod
- Local persistence: Drift (SQLite) for logs/analytics data; encrypted at rest
  (SQLCipher) because craving/context logs are sensitive wellness data
- The decision tree, swap lists, and whyLines live as versioned JSON assets, loaded and
  validated at startup — copy edits must never require logic changes
- Offline-first: every core flow (craving flow, logging, insights over local data) works
  with no network. No runtime AI calls in the craving flow.
- Charts for Insights: fl_chart or equivalent
- Stats engine (correlations, t-tests, chi-square, regression per the Insights spec):
  implement in pure Dart as an isolated, unit-tested package within the repo

## Architecture

Feature-first clean architecture:
- `core/` — theme, routing (go_router), shared widgets, utils
- `data/` — Drift schema, repositories, JSON tree loader + validator
- `features/onboarding/`, `features/craving_flow/`, `features/insights/`,
  `features/profile/`
- Domain logic (tree traversal, prior math, learning-loop updates, stats) pure Dart,
  UI-independent, fully unit-testable
- The tree engine takes a tree JSON + userTriggerMap and returns the next node — a pure
  function. The medical layer's hooks will later wrap this function; design the seams now.

## Product surface (all behavior per the spec docs — do not redesign)

1. Onboarding: craving-type opener, per-craving trigger mapping + timing, swap-preference
   picker with dietary-restriction filter. Skippable; skipping degrades gracefully.
2. Craving flow: prior-seeded root (confirm at weight ≥ 0.6 AND counts ≥ 5, else cold),
   sub-trigger question, intensity, intervention screen (whyLine → concrete action →
   swaps → conscious-choice fallback), urge-surf timer, did-that-help follow-up,
   transactional write of the flow log + map/efficacy updates.
3. Insights tab: background stats over local logs, plain-language cards with confidence
   states, progressive disclosure to real numbers, reflection flow, minimum-n gating.
4. Profile/settings: edit swap prefs and restrictions, notification preferences, data
   export (JSON) and full local data deletion.

## Production bar

- Theming: brand identity — deep green #04342C, accent #5DCAA5, Playfair Display for
  display type, DM Sans for body; light + dark mode; consistent design tokens
- Accessibility: semantic labels, dynamic type support, contrast-checked, screen-reader
  pass on every screen
- Error handling: no silent failures; corrupted/missing tree JSON fails loud in debug and
  falls back safely in release
- Testing: unit tests for tree traversal, weight math (α = 0.15 update + normalization),
  efficacy updates, confidence gating, restriction filtering, and the stats package;
  widget tests for the craving flow happy path and the skipped-onboarding path; a golden
  test for the intervention screen
- CI: GitHub Actions — analyze, test, build both platforms on every PR
- Versioned DB migrations from day one
- Privacy: all data local; no analytics SDKs, no trackers, no network transmission of
  logs. State this in a privacy screen in-app.
- App-store readiness: icons, splash, adaptive icons, correct bundle IDs, store-listing
  metadata drafted

## Guardrails (carry over completely — see handoff §7)

Genuine hunger/hangry always route to eating; permission branches stay permissive; no
shame, calorie, or weight framing anywhere; no diagnosis or medication advice; confidence
gating with "still learning" states; ED-risk-mode suppression rules honored in the swap
system; swaps never violate stated dietary restrictions.
